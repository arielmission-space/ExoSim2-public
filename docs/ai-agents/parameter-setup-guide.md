# Parameter setup guide for agents

This guide explains how to help users configure ExoSim without inventing
unsupported science or parameter defaults.

## Configuration loader facts

Evidence: `src/exosim/tasks/load/load_options.py`.

- Supported input extensions are `.xml`, `.yaml`, and `.yml`.
- XML is the dominant documented format in `docs/source/user/` and `examples/`.
- `<config>path</config>` entries include and merge another configuration file.
- `__ConfigPath__` is replaced with the active configuration path.
- A top-level or nested `<ConfigPath>` value can set the active path unless a
  `config_path` parameter is passed directly to `LoadOptions`.
- XML values are converted from strings to `int`, `float`, `True`, or `False`
  where possible.
- XML elements with a `unit` attribute are converted to `astropy.units.Quantity`.
  The special unit name `dimensionless` maps to no unit.
- If a parsed dictionary contains a `datafile` entry, the loader resolves it,
  checks that the file exists, and reads it with `astropy.table.Table`.
- Keywords whose element names start with `__` can be substituted into later
  string values with the `__name__` syntax.

## Parameter-help workflow

1. Identify the user goal: focal plane, radiometric model, sub-exposures, NDRs,
   full observation, or a standalone tool.
2. Ask for the configuration file path if it was not provided.
3. Read the main configuration and recursively inspect referenced `<config>`
   files before recommending edits.
4. Preserve units exactly. When suggesting a new value, state the unit and explain why it
   is required by the relevant documentation or code path.
5. Preserve `__ConfigPath__` for portable relative paths.
6. Check whether the parameter is documented in `docs/source/user/` or used by a
   task in `src/exosim/tasks/` before claiming it is valid.
7. For runtime controls, use `RunConfig` or CLI flags rather than adding science
   parameters to XML:
   - thread count: CLI `--nThreads` or `RunConfig.n_job`
   - chunk size: recipe/CLI options where available, or `RunConfig.chunk_size`
   - random seed: configuration `random_seed` or `RunConfig.random_seed`

## Pipeline selection quick reference

- Focal-plane creation: use `exosim focalplane -c CONFIG -o OUTPUT` or
  `recipes.CreateFocalPlane`.
- Radiometric model: use `exosim radiometric -c CONFIG -o OUTPUT` or
  `recipes.RadiometricModel`.
- Sub-exposures: use `exosim subexposures -c CONFIG -i INPUT -o OUTPUT`, the
  `exosim-sub-exposures` console script, or call `recipes.CreateSubExposures`.
- NDRs: use `exosim ndrs -c CONFIG -i INPUT -o OUTPUT` or `recipes.CreateNDRs`.
- End-to-end observation support is provided by `src/exosim/recipes/simulate_observation.py`
  and is exposed through the CLI where available in the checked-out branch.

## Safety checks before answering

- If a parameter is not present in examples, docs or code, call it an open
  question rather than supplying a guessed default.
- If a file path points to data (`datafile`, maps, PSFs, QE maps), verify whether
  it is intended to be generated by a tool or supplied by the user.
- If a configuration includes multiple channels, inspect each channel separately;
  do not assume detector/readout settings are shared.
- For stochastic runs, call out the `random_seed` value and whether it is fixed
  or absent.
